### 1.3 ECX 到底是什么：调用点实证

调用点 2（`Control.cpp` @ `0x60B950`）：`cmp esi, 0D7h / 108h / 0BCh …; mov ecx, esi; call Dialog__IsSpecialTemplate`。

> `edi`/`esi` 是**对话框 ID**：调用方在传给函数前，正把它与同一 ID 空间（`0x6B..0xBC7`）的常量逐项比较。ECX 装载的是这个整数 ID，不是对象指针。

### 1.4 过拟合机制（逐层）

1. **二进制层**：函数只读 ECX，与 18 个小整数比较后返回 0/1。它等价于 `int f(int id)`（首参在 ECX 即 `__fastcall`），无 `this` 对象参与。
2. **proto 层**：IDA 把唯一入参寄存器 ECX 解释为该类的 `this`（`// proto: int __thiscall(Dialog *this)`），Hex-Rays 于是把伪码渲染为 `this == (Dialog *)293`。**类型错误发生在 proto/伪码层，不在 codegen 层**。
3. **生成层**：`decompile.derive_signature` 接受 registry 的 `cc=thiscall` + `cls=Dialog` + `ret=int`，`passes` 对 `this` 无成员可恢复（本来就没有内存访问），原样 emit。生成器对伪码是**忠实**的——荒谬代码逐字来自 Hex-Rays。
4. **C++ 语义陷阱**：`this == (Dialog *)293` 是合法的 C 风格转换；VC6 编译为 `cmp ecx, 125h / jz`，与整数比较**逐字节相同**。类型信息在编译后完全消失。
5. **字节门禁**：`diffasm` 只比较规范化字节（jcc 目标/rel32 符号/DATA 掩码），不是类型检查器；161B 全等 → `MATCH`。
6. **规则门禁**：旧 `checker.py` 只查 R3/R4（指针算术/成员偏移/成员 pun），**没有“指针 vs 小整数”的语义规则** → 0 违规。
7. **账本层**：`batch_run` 的 verdict 只由字节 `ok` 决定；`rule_violations` 只记录不 gate；`era cl` rc=0（无警告）→ ledger `OK`。

**结论**：这是“**proto 类型被字节层无条件继承**”的过拟合，不是形态巧合。字节匹配与荒谬 C++ 可以共存，因为 32 位 x86 上“指针比较”和“整数相等比较”生成相同指令。

### 1.5 堵法（已实施）

#### (a) checker 新语义规则 R7（`this-as-id`）

`tools/decomp_sys/checker.py` 新增：

### 1.6 diffasm 是否需要改？

不需要。此案例证明的是 **字节层无法表达类型**，不是掩码过宽：`cmp ecx, imm` 对指针/整数两种源码是同一条指令。加固点必须放在 **签名/语义层**（checker R7 + decompile 仲裁），字节层保持“只做字节”的职责边界。

## 2. ② checker R3/R4 盲区（43/424）

### 2.1 性质判定（先判性质，再修）

对修复前产物（`rem_before43`）重跑旧 checker：

| 构造 | 旧 checker | 性质 |
|---|---|---|
| `*((unsigned int *)this + N)`（40 件） | `R4 ptr+int` + `R4 cast-ptr+int` = 2 条 | **同一构造双计**：两个正则覆盖同一段源码；但底层是**真违规**（对类接收者做裸偏移访问，R3 精神） |
| `(char *)this + N`（2 件） | `R4 ptr+int` + `R4 cast-ptr+int` = 2 条 | 同上；地址型裸偏移（无解引用）→ R4 |
| `(char *)(&this->attachedBomb)`（1 件） | `R3 member-pun` = 1 条 | 真违规（成员地址 cast 到外部指针类型） |
| `(Queue *)(&this->field)`（0x408520，审计指出的盲区） | **0 条** | 旧 member-pun 正则要求 `)&` 紧邻，实际是 `)(&` → **漏报** |

> 结论：43 是**函数口径的下界**（真违规），不是 checker 误报；但“每件 2 条”是 checker 的 span 记账缺陷。修复方向 = **保留违规、去重计数、补上漏报形态**，不是放宽规则。

### 2.2 checker 修复（只增强）

1. **新增嵌套 cast-deref 规则**（覆盖 `*((T *)this + N)`）：
   ```python
   for m in re.finditer(r"\*\s*\(\s*%s\s*%s\s*\+\s*(?:0x)?\d+\s*\)" % (_CAST_HEAD, nm), text):
       flag("R3", "cast-deref-plus", ...)
   ```
2. **span 去重**（`_dedupe_spans`）：同一源码区间只保留最长/最具体的一条。`*((T*)this+N)` → 1 条 R3，不再是 2 条 R4。独立构造互不吞并。
3. **member-pun 正则补 `(` 变体**：`%s\s*\(?\s*&\s*this->` —— `(Queue *)(&this->m)` 现在命中 R3 member-pun。
4. **新增 R7**（见 §1.5a）。
5. 未改动 R1/R2/R5/R6 语义；`undeclared member` 检查保留。

### 2.3 decompile 修复（产线不再生成）

#### (a) `pass_this_ptr_math` 扩展（`tools/decomp_sys/passes.py`）

新增三种形态（按宽度选 view，**字节同构**）：

- `*((T *)this + N)` → `this->m<off>`：读宽 = `sizeof(T)`，`byte_off = N * sizeof(T)`；registry 有同宽成员则复用其名，否则合成 `m%03X` 占位 view（hpp 同步声明）。
- `(T *)this + N`（无解引用）→ `this->m<off>` 的 **char 数组 view**（`char m... [1]`，衰减即地址；`lea` 同构）。
- 裸 `this + N`（proto this 为指针）→ 同上（按 proto 元素宽度缩放）。

#### (b) 新 pass `pass_member_addr_view`

- `(T *)&this->m` / `(T *)(&this->m)` → `this->m<off>`（char 数组 view）。
- `0x634800`：`return (char *)((char *)&this->attachedBomb);` → `return (char *)(this->m038);`；hpp 在同偏移生成 union `{ char m038[1]; int attachedBomb; }`（既有成员名不丢失）。

### 3.2 类归属链修复

#### (a) registry（`registry.py`）

- **sentinel 拒绝**：`{"unknown","Unknown","UNKNOWN","?","none","None","null","NULL","","Return"}` 不再作为类身份；`bf_cls`/`sig_cls` 先过滤，再走 `vsa_owner`（唯一主表 owner）→ `name_prefix`（必须是合法标识符且非 sentinel）。
- 统计键 `cls_sentinel_dropped`。

#### (b) NO_CLS 解析器（`registry_ext.resolve_function_class`）

- 同样的 sentinel 过滤（vsa / proto_this / name_prefix 三通道），防止 `Return`/`unknown` 被回收。

#### (c) decompile proto 仲裁（`decompile.derive_signature`）

- 旧逻辑：proto `T *this` 只要 `T` 在 registry 且 ≠ 当前类，就无条件覆盖（**53 处会把成员函数扩宽/迁到无关类**，例如 `BulletClass::Fire` 被 proto 的 `ObjectClass*` 重归属、`CampaignClass::LoadFromINIList` 被 `INIClass*` 重归属）。
- 新逻辑：**只接受“派生收窄”** —— `T` 必须与 registry 类同源，且 registry 类是 `T` 的祖先（RTTI `anchors/rtti_base_arrays.json` 全基类表 + `class_layouts` parent 链，954 类二进制真值）；否则保留 registry 类并记录 `proto_this_rejected`。
- 对 3 件 OK proto_this：`ShpButtonClass←GadgetClass`、`DynamicVectorClass←VectorClass`、`TechnoClass←ObjectClass` 均为派生收窄 → 保持（与布局证据一致）。

#### (d) 账本（`batch_run.record_ledger` + `ledger.record`）

- `name` 写 **emitted**（有效身份），`orig_name` 保留原 signals 名，另记 `cls_src`、`rule_violations`、`clean`、`this_as_id`。
- `clean = verdict==MATCH && rule_violations==0`（可观测的“干净 MATCH”信号）。

#### (e) 自由函数 __stdcall 仲裁（顺带修复）

- `Return::HRESULT_Fail`（0x48ACE0）二进制为裸 `__stdcall` 3 参（`mov eax,-15; retn 0Ch`）。sentinel 过滤后 `cls=None` → 自由函数通道；arity 计算改为“自由 stdcall 不减隐式 this”，得到 `int __stdcall HRESULT_Fail(int p0,int p1,int p2)`，**MATCH**。
